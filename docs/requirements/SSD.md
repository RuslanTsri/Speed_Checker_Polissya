# System Specification Document (SSD) — Tempo Metrics

**Версія:** 1.0.0 
**Статус:** Draft
**Проєкт:** Мобільний застосунок для аналізу спортивних показників

## 1. Огляд системи
Tempo Metrics — це програмно-апаратний комплекс для автоматизації вимірювання швидкісних характеристик спортсменів за допомогою Bluetooth-сенсорів (гейтів).

## 2. Системна архітектура
Система базується на клієнт-серверній архітектурі з використанням мобільного додатка як центрального хаба:
* **Client:** React Native (Expo) мобільний застосунок.
* **Hardware Interface:** Bluetooth Low Energy (BLE) для зв'язку з оптичними гейтами. Lora для забезпечення зв'язку між головним гейтом (Мастер) та іншими.
* **Backend as a Service:** Supabase (PostgreSQL, Auth, Storage).

## 3. Технічний стек
* **Frontend:** React Native, TypeScript, Tailwind CSS (NativeWind).
* **State Management:** React Context API + Custom Hooks.
* **Database:** PostgreSQL (Supabase).
* **API:** RESTful API через PostgREST.

## 4. Функціональні вимоги (Functional Requirements)
* **FR1: Комунікація з BLE.** Система повинна сканувати, підключатися та отримувати дані від 2 або 3 гейтів одночасно.
* **FR2: Профілі команд.** Можливість створення команд та масового імпорту гравців через .csv/.xlsx.
* **FR3: Режими тестування.** Підтримка режимів "Гість" (швидкий замір) та "Команда" (збереження в базу).
* **FR4: Оновлення OTA.** Підтримка оновлень інтерфейсу без перевстановлення додатка через Expo Updates.

## 5. Нефункціональні вимоги (Non-functional Requirements)
* **Продуктивність:** Обробка сигналу від гейта повинна відбуватися з затримкою не більше 150 мс.
* **Відмовостійкість:** У разі втрати зв'язку з БД, дані мають кешуватися локально (AsyncStorage).
* **Безпека:** Відповідність стандартам GDPR щодо збереження персональних даних атлетів.
